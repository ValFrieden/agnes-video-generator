# Сценарный стандарт непрерывности (Continuity Lock & Identity-vs-Variant)

> **Статус**: 🟡 **СТАНДАРТ ПРОЕКТА (обязателен для сценариев и раскадровок)**
> **Основание**: перенос методологии из `drama-skills` (MIT, см.
> `.agents/skills/THIRD_PARTY_NOTICES.md`) в собственный код проекта.
> **Реализация**: `core/screenwriter/scenario_director.py`
> (`ContinuityLock`, `build_character_bible`, `review_project`).

---

## 1. Три идеи, которые мы применяем

### 1.1. Идентичность против состояния (Identity vs Variant)

Каждый видимый признак персонажа относится ровно к одной из двух групп:

| Группа | Смысл | Пример | Поле в коде |
|---|---|---|---|
| **Идентичность** | если изменить — это уже другой человек | форма лица, цвет глаз, цвет и текстура волос, шрамы | `CharacterProfile.identity_anchors` |
| **Состояние** | тот же человек, но вид изменился по сюжету | мокрый плащ, ссадина, сумерки, капюшон надет | `CharacterProfile.state_variants` |

Состояние **никогда** не попадает в идентичность. Ошибка класса «в акте 2 герой промок,
запишем в идентичность» порождает дрейф: модель начнёт генерировать мокрого героя в сухих сценах.

### 1.2. Замок непрерывности (Continuity Lock)

Замок — **минимальная именная группа на языке промпта**, которую нельзя перефразировать:

```
identity  → grey-green eyes
grooming  → short matte brown hair
wardrobe  → indigo wool overcoat
prop      → bronze wristwatch with cracked glass
```

Правила написания замка:

1. 2–6 слов, нижний регистр, без пунктуации в конце.
2. Одно и то же написание везде (включая регистр) — иначе машинная проверка не найдёт его.
3. Замок копируется в **каждый** `video_prompt` дословно.
4. Замок описывает только то, что не меняется по сюжету; изменяемое — состояние (§1.1).

`ScenarioDirector.format_continuity_lock_block()` собирает из замков готовую строку для промпта.

### 1.3. Проверка до траты кредитов (Review перед производством)

`ScenarioDirector.review_project()` — **детерминированная** проверка, без вызова LLM.
Формулировки уровня «убедительно ли это» остаются человеку; проверяется только то, что
можно проверить фактами.

| ID | Серьёзность | Что проверяется |
|---|---|---|
| `SCN-00` | blocker | раскадровка не пуста |
| `SCN-01` | blocker | в каждом `video_prompt` стоят все замки непрерывности дословно |
| `SCN-02` | blocker | `video_prompt` не пустой |
| `SCN-03` | blocker | у кадра есть доминирующая эмоция (1 Shot = 1 Emotion) |
| `SCN-04` | warning | указан монтажный переход |
| `SCN-05` | warning | сумма длительностей сходится с целевым хронометражем (±0.5 с) |
| `SCN-06` | warning | число сцен соответствует запросу |
| `SCN-07` | blocker | нет слов, провоцирующих липсинк (рот закрыт — железное правило) |
| `SCN-08` | warning | сквозной реквизит не дублируется внутри одного промпта |
| `SCN-09` | blocker | есть `anchor_token` персонажа |
| `SCN-10` | blocker | карточка персонажа полная: `front`, `three_quarter`, `profile`, `back`, `fullbody` |
| `SCN-11` | warning | заданы `continuity_locks` |

Вердикт: наличие любого `blocker` → `REVISE`. Вывод печатается в Markdown-экспорт
(`export_to_markdown`, раздел «Проверка сценария») и попадает в `ScenarioProject.review`.

## 3. Где это в интерфейсе

`frontend/src/components/ScenarioStudioPanel.vue` (вкладка «Создание» → тип `creative`,
под формой) — единственный потребитель `POST /api/scenario/generate`:

- поля: идея, стиль, длительность, BPM, число кадров, лейтмотив;
- результат: вердикт проверки (`OK` / `REVISE`) + список `SCN-*`, Character Bible с
  чипами `continuity_locks`, доска раскадровки (карточка на кадр), экспорт в Markdown;
- клиент: `generateScenario()` в `frontend/src/api/index.ts`.

До 2026-10-30 эндпоинт был реализован, но **не имел ни одного потребителя во фронтенде** —
это и было главным разрывом автоматизации: сценарий создавался только руками через
`scripts/create_scenario.py`.

## 4. Где это в конвейере

```
Сценарий (ScenarioDirector)          → review_project(): SCN-01…11
        ↓
Карточка персонажа (5 ракурсов)      → SCN-10 блокирует без полного turnaround
        ↓
Ключевые кадры / референсы           → привязка к карточке (см. mandatory_reference_pipeline.md)
        ↓
Видео по кадрам                      → контакт-лист 25/50/75% на каждый клип (QC-Trio)
        ↓
QC-гейт (opt-in, VLM)                → core/quality/qc.py ClipQCGate
```

**QC-Trio** — это `scene_{i}/qa_trio.png` / `para_{i}/qa_trio.png`, собирается
`core.quality.qc.build_contact_sheet()` сразу после генерации видео
(`MultiScenePipeline._write_all_contact_sheets`). Артефакт `qa_trio` виден в UI под
шагом видео. Он не заменяет VLM-гейт, а делает ту же точку проверяемой для человека.

## 5. Чего делать нельзя

1. Писать замок как предложение или с эпитетами («красивые пронзительные серо-зелёные глаза») —
   его нельзя будет проверить и он раздует промпт.
2. Класть в замки то, что меняется (состояние, свет, настроение).
3. Считать `warning` разрешением игнорировать: `SCN-08` (дубли реквизита) ломает кадр так же,
   как блокер — модель рисует два зонта.
4. Заменять `review_project()` «на глаз»: проверка бесплатна и выполняется за миллисекунды,
   трата кредитов на генерацию до неё — неоправданна.
