# Диагностика: симптом → причина → решение

| Симптом | Причина | Что делать |
|---|---|---|
| «Ничего не происходит», запрос не уходит, поле запроса с текстом остаётся | **кнопок «Generierung starten» несколько**; раньше клик шёл по первой, не рабочей. Исправлено 27.10.2026 (`SUBMIT_CLICK_JS`, проверка очистки поля) | убедиться, что код свежий; снимок страницы; поле должно очиститься после отправки |
| Запуск «висит» без вывода | вывод фильтровали `\| tail`/`grep`, пока процесс не закончился | запускать в фоне, читать лог-файл; не фильтровать долгие команды |
| `Failed to attach reference image` | элемент не найден, чип не добавился, открыто чужое меню | снимок страницы; запуск с абсолютными путями; повтор (один раз сбой был разовым) |
| Цены нет, агент задаёт вопрос | запросили недоступную длительность (6 с) | брать 8 с (`normalize_duration`) |
| `ECONNREFUSED 127.0.0.1:9222` | Chrome закрыт вместе с приложением | запустить `launch_chrome.ps1`, при необходимости войти в Flow |
| Скачивание «720p not found» / «failed within 45s» | плитка открывала редактор повторно; ждали папку Downloads | кнопка из открытого редактора + `expect_download` (сделано) |
| Растянутая или с полосами героиня в клипе | стартовый кадр не 16:9 | `flow_pipeline check`, готовить 16:9 |
| «Фазы» вместо плавного превращения | два кадра с разной композицией | генерировать 3D-версию из самого фото, делать морфинг (`morph`) |
| Правка не применяется / «permission aborted» | команда с `rm -rf` запрещена; приложение перезапущено и сбросило режим | не использовать `rm -rf`; снова включить Bypass |
| Тесты падают на `PermissionError ...pytest-of-Valeri` | нет прав на стандартный Temp | `--basetemp=<scratchpad>/pt` |
| Тест на DOM пропущен | нет Chrome :9222 | запустить Chrome |
| `Das Token "&&" ist kein gültiges Anweisungstrennzeichen` | Windows PowerShell 5.1 не поддерживает оператор `&&` | использовать `;` вместо `&&` либо `npm --prefix frontend test` и `npm --prefix frontend run build` |
| Подозрение, что кредиты списаны дважды | повторная отправка | `status` и `flow_state/credits.jsonl`; `ShotAlreadySubmittedError` защищает от повтора |
| Запуск кончается «Render timed out», в чате Flow «scheduled and waiting in the queue due to high demand» | очередь Flow при высокой нагрузке (S17 v3: часы; S19: ~40 мин); кредиты резервируются, клип появится позже новой плиткой | **не отправлять повторно**; через время открыть библиотеку Flow, найти плитку по содержимому, скачать отдельно; сверить хэш |
| Движок пишет «rendered/fertig», но файл совпадает по размеру и хэшу со старым клипом | сработал счётчик плиток, плитка с индексом 0 не новая | всегда сверять `Get-FileHash` с предыдущим клипом, смотреть контактный лист; состоянию `shots.json` в таком случае не доверять |
| «Clip … already exists. Skipping.», генерации нет | движок пропускает, если целевой файл уже есть | перед пересъёмкой сохранить старый клип как `clip_NN_v1.mp4` и удалить оригинал; до этого `new_version` |
| `ShotAlreadySubmittedError` при пересъёмке | шот уже отправлен в этой версии | `ShotStateStore.new_version('Sxx', reason=...)`, затем запуск |
| «Download button not found» / «Download menu item '720p' not found» | редактор клипа не успел открыться или меню не отрисовалось (разовый сбой по времени; в меню есть «720p / Originalgröße») | повторить скачивание отдельно, не отправляя запрос заново; `*.flow_pending.json` не трогать, пока клип не скачан |
| Скриншот Flow висит / скрипт зависает | два скрипта Playwright одновременно работают с одной вкладкой Flow (перезагрузка страницы) | не запускать два скрипта параллельно; для снимка использовать `Page.captureScreenshot` через CDP |
| Видео совсем не похоже на keyframe | Omni R2V использует кадр как образец | если нужна точная композиция, Veo Fast I2V (лист не прикладывается), решение согласовать с автором |

## Общие правила диагностики
1. Сначала снимок экрана страницы Flow (`Page.captureScreenshot` через CDP) и количество карточек цены / плиток видео.
2. Не повторять отправку, пока не ясно, что предыдущая не ушла (иначе двойные траты).
3. Для вопросов о Flow пользоваться Perplexity (`perplexity_ask`), результат писать в `flow-facts.md`.

## Предупреждение Flow об «ungewöhnliche Aktivitäten» (30.10.2026, S26)
- Симптом: после одобрения цены в чате Flow сообщение «Wir haben ungewöhnliche Aktivitäten festgestellt… Browsererweiterungen…» и кнопка «Noch einmal versuchen», клип не рендерится, запуск уходит в тайм-аут; шот в `shots.json` остаётся APPROVED.
- Это защита Flow от автоматизации. Не обходить и не повторять отправку скриптом: повтор может списать кредиты ещё раз. Решение: автор сам нажимает «Noch einmal versuchen» в Chrome, потом клип скачивается отдельным скриптом без новой отправки.

## Правила на основе решённых проблем S27–S28 (30.10.2026): как решали → как делать всегда
1. **Повторяющийся предмет (торт) должен выглядеть одинаково.** Решение: вырезать предмет из последнего кадра предыдущего клипа (`ffmpeg ... -vf "crop=W:H:X:Y,scale=..."`, аргументы crop через двоеточие), сделать из него лист предмета (`core.flow_pipeline image --ref crop --prompt "turnaround sheet ... exactly SEVEN candles"`, число свечей цифрой), положить в `masha_frames/props/`. Правило: для каждого предмета, который встречается в двух и более кадрах, сначала лист предмета, потом кадры.
2. **Лист героя + лист предмета + кадр, а Flow принимает только 2 картинки.** Решение (идея автора): склеить листы в одну картинку `ffmpeg -i hero.jpg -i prop.jpg -filter_complex "[0:v]scale=1376:-2[a];[1:v]scale=1376:-2[b];[a][b]vstack" refs.jpg` (пример `props/refs_masha_cake_v1.jpg`). Первой картинкой идёт кадр, второй склейка; в промпте описать, что в верхней и нижней частях склейки. Правило: больше 2 вложений никогда, склеивать.
3. **Следующий кадр должен продолжать предыдущий клип.** Решение: последний кадр `ffmpeg -sseof -0.1 -i clip.mp4 -frames:v 1 frame.png` как референс; детали (число свечей, подарок, берег) сверять с ним и править сценарий, если он устарел (S28: задуваем все 7 свечей, а не одну).
4. **Автор говорит «переделать кадр» без пояснений.** Сделать новую версию (бесплатно), сразу исправив явные недостатки (обрезанные предметы), показать и учесть уточнение автора. Кадры бесплатны, видео только после явного «да».
5. **Статус шота.** Только enum: `from core.flow_shot_state import ShotStatus` (не `core.flow_state`), `advance('S27', ShotStatus.RENDERED)`, затем `ShotStatus.DOWNLOADED`. Строка вместо enum даёт TypeError.
6. **Скачивание принятого клипа.** Порядок: дождаться задачи скачивания, проверить размер и md5 против прошлых клипов, контактный лист, удалить `clip_NN.mp4.flow_pending.json` только после этого, статус DOWNLOADED, строка в production-log, показать автору.
7. **Сбой «expected 1 chips after attaching … found 0» при запуске видео.** Движок повторяет сам. Не убивать и не перезапускать скрипт: после отправки статус APPROVED, кредиты зарезервированы. Сначала `core.flow_pipeline status` и вывод фонового скрипта; повторный запуск только по слову автора.
8. **«Дальше» от автора во время ожидания видео** не разрешает новый запуск; продолжать только проверку и скачивание.
